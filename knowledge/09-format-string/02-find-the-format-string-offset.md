# 找到输入落在第几个参数

上一篇看到，输入 `%p.%p.%p.%p.%p.%p` 时，第六个打印出来的值就是输入本身。这一篇把「第六个」这件事从一次观察变成一个方法：不靠数 `%p`，直接说出输入在第几个参数。

还是 x86-64、GCC 15.2.0、glibc 2.43。这个序号来自 `buf` 在栈上的位置和寄存器参数的数量，不依赖 glibc 版本。换一个编译器、换一个优化级别，序号会变，方法不变。

## 用不会撞车的字节做标记

`labs/09-format-string/probe.c` 和上一篇的 `fmt.c` 是同一个程序，单独放一份，避免两篇的实验互相改。

按 README 编译。输入一串容易认的字节，再跟上八个 `%p`：

```bash
python3 -c 'import sys;sys.stdout.buffer.write(b"AAAABBBB.%p.%p.%p.%p.%p.%p.%p.%p\n")' | ./probe
```

输出类似：

```text
AAAABBBB.0x687f011.0x7071eba14760.0x7071eba14760.0x687f031.(nil).0x4242424241414141.0x252e70252e70252e.0x2e70252e70252e70
```

前五个是寄存器里的残留，每次运行都变。第六个是 `0x4242424241414141`。

按小端拆开：`41 41 41 41 42 42 42 42`，也就是 `AAAA` 然后 `BBBB`。这是输入的前 8 个字节。

标记要选不会自然出现的字节。`AAAA` 和 `BBBB` 连在一起的概率足够低，看到 `0x4242424241414141` 就可以确定这是自己的输入，不是栈上碰巧的值。

## 为什么是第六个

先别看下面的解释。用你刚才的输出自己数：第一个点后面是第几个 `%p` 的结果，`0x4242424241414141` 出现在第几个点之后。

数完再看原因。`%p` 从格式串之后的第一个参数开始取。第一个 `%p` 取 `rsi`，第二个取 `rdx`，第三个取 `rcx`，第四个取 `r8`，第五个取 `r9`。这是五个寄存器，对应你输出里前五个每次运行都变的值。第六个 `%p` 开始取栈，而 `buf` 正好在栈上参数的第一个槽，所以第六个读到输入的开头。

这个「第六」有两层来源，缺一不可。前五个被寄存器占了，这是 ABI 固定的，所以序号不可能小于 6：栈上的东西排在五个寄存器之后。`buf` 恰好落在栈上的第一个槽，这是编译器排栈的结果，不是必然的。换一个函数、让 `printf` 之前还有别的局部变量，`buf` 就会往后挪，序号就会比 6 大。所以 6 是这个程序测出来的，不是一个可以记住的常数。

## 直接读第 n 个

一个个 `%p` 往下数容易数错，也要求你把整串输出都看完。`printf` 允许在格式符里写序号：`%6$p` 表示直接取第六个参数，不管前面取了没有。

```bash
python3 -c 'import sys;sys.stdout.buffer.write(b"AAAABBBB.%6$p\n")' | ./probe
```

输出：

```text
AAAABBBB.0x4242424241414141
```

和上面数出来的第六个相同。`AAAABBBB.` 是格式串里的普通字符，照样输出；`%6$p` 只取第六个参数。

`$` 在 shell 里有特殊含义，所以这里用 Python 把字节写进去，不经过 shell 解释。如果直接在 shell 里写 `%6$p`，`$p` 会被当成变量。

再用相邻的两个序号确认没有看错：

```bash
python3 -c 'import sys;sys.stdout.buffer.write(b"AAAABBBB.%5$p\n")' | ./probe
python3 -c 'import sys;sys.stdout.buffer.write(b"AAAABBBB.%7$p\n")' | ./probe
```

第五个是 `(nil)` 一类的残留，第七个是 `0x252e70252e70252e` 附近的值，拆开是 `.%p.%p.`，那是输入更后面的字节。只有第六个是 `AAAABBBB`。

## 这个序号不是 buf 的长度

`buf` 声明为 128 字节。128 除以 8 是 16，和 6 没有关系。序号取决于 `buf` 的起始地址落在 `printf` 的第几个参数槽上，不取决于 `buf` 有多大。

`buf` 多大只影响你能放多长的格式串。在这个程序里 `fgets` 读 128 字节，所以格式串最长就是这么多。这是长度限制，不是偏移。

## 自己做一遍

1. 把标记换成 `CCCCDDDD`，重复一次，确认读到的值变成 `0x4444444443434343`。
2. 只用 `%6$p`，不看整串 `%p` 输出，判断输入是否在第六个参数。再用 `%5$p` 和 `%7$p` 证明两边都不是。
3. 在 GDB 里停在 `call printf`，用 `p/x $rdi` 得到 `buf` 的地址，用 `x/gx` 看栈，找出栈上哪一个槽的地址等于这个值。这个槽就是序号 6 对应的位置。

## 学完这一节，你应该能够

- 用一串特征字节在 `%p` 的输出里定位自己的输入，并说出它是第几个参数。
- 用 `%n$p` 直接读这个参数，并验证结果和逐个数出来的一致。
- 解释这个序号来自寄存器参数的数量加上缓冲区在栈上的位置，而不是来自缓冲区的声明长度。
