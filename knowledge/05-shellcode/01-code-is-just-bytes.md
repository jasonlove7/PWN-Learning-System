# 机器码放进内存并被执行

栈那一节停在一个事实上：返回地址可以被覆盖，于是返回时 `rip` 会去你放进去的那个地址。当时没有回答的问题是，去了之后 CPU 会做什么。

这一篇回答它。CPU 不关心要执行的字节来自 ELF 的 `.text`，还是来自你放进内存的一段数据。它只看 `rip` 指向哪里，就从那里取指令。

## 一段最小的机器码

先看两条指令：

```text
mov eax, 0x42
ret
```

第一条把 `0x42` 写进 `eax`。第二条返回。这两条在汇编那一节都见过，这里不重复它们的含义。

把它们汇编成字节：

```text
b8 42 00 00 00
c3
```

`b8` 是 `mov eax, 立即数`，后面 4 个字节是立即数 `0x42`，小端。`c3` 是 `ret`。一共 6 个字节。

这 6 个字节就是这一篇要用的全部机器码。它不做别的事，只改一个寄存器然后返回，所以执行完之后程序还能继续，方便观察。

## 放进缓冲区

`labs/05-shellcode/run.c`：

```c
unsigned char buf[32];
unsigned char code[] = { 0xb8, 0x42, 0x00, 0x00, 0x00, 0xc3 };

memcpy(buf, code, sizeof(code));

int (*fn)(void) = (int (*)(void))buf;
int result = fn();
```

`buf` 在栈上。`memcpy` 把那 6 个字节抄进去。`fn` 是一个函数指针，指向 `buf`。调用 `fn()` 就是把 `rip` 送进 `buf`。

这里用函数指针而不是覆盖返回地址，是为了让实验只包含一件事：跳到一段自己放进去的字节。覆盖返回地址那一步栈那一节已经做过，不在这里重复。两件事合在一起才是完整的利用，这一篇只看第二件。

按 `labs/05-shellcode/README.md` 编译。注意 `-z execstack`：这个实验要执行栈上的字节，所以栈必须可执行。这是为了构造教学环境，不是正常程序该有的编译方式。现代系统默认不让栈执行，那是后面要处理的问题，这里先放开。

直接运行：

```bash
./run
```

打印 `result=66`。`66` 就是 `0x42`。`eax` 里的值被 `main` 取回来，当成返回值打印了。

## 看它真的被执行了

运行结果只能说明值对了，不能说明这 6 个字节被执行了。值也可能是别的地方算出来的。用 GDB 看执行过程。

```bash
gdb -nx -q ./run
```

```text
(gdb) set debuginfod enabled off
(gdb) set disassembly-flavor intel
(gdb) disas main
```

找到 `call rax` 那一行。在这一版编译结果里它在 `0x401169`。用你看到的地址：

```text
(gdb) b *0x401169
(gdb) run
```

停在 `call rax` 上。`rax` 里是 `buf` 的地址。看它指向的字节：

```text
(gdb) x/6xb $rax
```

输出：

```text
0xb8  0x42  0x00  0x00  0x00  0xc3
```

和放进去的 6 个字节一致。地址每次运行不同，字节不会变。

执行这一条 `call`：

```text
(gdb) si
(gdb) x/2i $rip
```

`rip` 现在指向 `buf` 的地址，而不是 `main` 里的任何一条。反汇编出来是：

```text
mov eax, 0x42
ret
```

GDB 把栈上的字节当成了指令。这不是因为这些字节有什么标记，是因为 `rip` 指向了它们。

再走一条：

```text
(gdb) si
(gdb) p/x $eax
```

`eax` 是 `0x42`。执行前它不是这个值，是 `call` 之前残留的内容。

再走一条，`ret`：

```text
(gdb) si
(gdb) x/i $rip
```

`rip` 回到了 `main` 里 `call rax` 的下一条。`ret` 从栈上取回了返回地址，和函数调用那一节的行为一样。区别只在于这次被调用的不是一个函数，是 6 个字节。

## 为什么这样就能执行

CPU 取指令的方式只有一种：从 `rip` 指向的地址读字节，按指令编码解释。它不检查这些字节是不是链接器放进 `.text` 的，也不检查这块内存是不是你用 `memcpy` 写进去的。

所以「代码」和「数据」的差别不在字节本身，在于有没有人把 `rip` 指过去。ELF 里 `.text` 是可执行的，只是因为加载时那段的权限设成了可执行。栈默认不可执行，是同一件事的反面：权限没给，`rip` 指过去也会被拒绝。

这一篇把权限给了，所以指过去就能执行。权限不给的时候会怎样、那种情况下怎么继续，是下一模块的问题。

## 这和 shellcode 的关系

这段 6 字节的机器码就是一个 shellcode，尽管它没有启动 shell。

shellcode 指的是一段准备放进目标进程、并让执行流进入它的机器码。名字里的 shell 来自早期最常见的用途是启动一个 shell，不是定义的一部分。一段只改寄存器的机器码，和一段启动 shell 的机器码，在「被放进内存、被跳进去执行」这一点上没有区别。

这一篇只建立这个模型。怎么写出一段做更多事的机器码，后面再讲。

## 自己做一遍

1. 把 `0x42` 改成 `0x99`，重新编译运行，确认打印的值变了。再用 GDB 看 `x/6xb`，确认变的是第二个字节。
2. 在 `call rax` 之前和 `si` 一次之后各看一次 `rip`，确认它从 `main` 里的地址变成了 `buf` 的地址。
3. 解释为什么 `ret` 之后程序没有崩溃，而是回到了 `main`。答案在栈上，不在这 6 个字节里。

## 学完这一节，你应该能够

- 把 `b8 42 00 00 00 c3` 逐字节对应回 `mov eax, 0x42` 和 `ret`。
- 在 GDB 里指出缓冲区地址、里面的 6 个字节，以及 `rip` 跳进去之后停在哪一条指令。
- 解释这段字节被执行是因为 `rip` 指向了它，不是因为它来自 `.text`。
